# gitsync

This project automatically synchronizes repositories from AtomGit to GitHub using a scheduled GitHub Action.

## How It Works

The synchronization process is driven by a GitHub Actions workflow defined in `.github/workflows/gitsync.yml`. Here's a step-by-step breakdown:

1.  **Scheduled Trigger**: The workflow is configured to run every 5 minutes.
2.  **Checkout**: It checks out this repository and a separate private repository named `conf`. The private `conf` repository is expected to contain sensitive credentials.
3.  **Setup**: It sets up the `bun` runtime environment and installs dependencies from `package.json`.
4.  **Authentication**: The workflow configures authentication by linking SSH keys from the `conf` repository (`conf/ssh`) and loading environment variables from `.env` files within `conf/gitsync`.
5.  **Execution**: The `run.sh` script is executed, which in turn runs the main synchronization script `main.js`.
6.  **Synchronization**: The `main.js` script utilizes the `@3-/gitsync` library to synchronize all repositories from the `js0` organization on AtomGit to the `js0-site` organization on GitHub. The `sync.yml` file is used to maintain the synchronization state and is automatically managed by the script. It automatically creates repositories on GitHub if they don't exist. **The [@3-/gitsync](https://www.npmjs.com/package/@3-/gitsync) library also leverages a Large Language Model (LLM) to automatically generate descriptive Git commit messages for the synchronized changes.**
7.  **Self-Update**: If any files in this repository (like `sync.yml`) are modified during the process, the workflow commits and pushes the changes back to the `main` branch.

## Configuration

To adapt this project for your own use, you need to configure the following:

### `sync.yml`

This file is automatically generated and managed by the `@3-/gitsync` library to keep track of the synchronization state of the repositories. It stores information about the last synced commits, which prevents re-syncing unchanged repositories and ensures a consistent state.

You should not manually edit this file unless you need to resolve a conflict or reset the synchronization state for specific repositories. The file's content looks something like this, mapping repository names to their synchronization data:

Example:
```yaml
repo-one:
  - <some_sync_data>
repo-two:
  - <some_sync_data>
```

### Private `conf` Repository

A private GitHub repository is required to store sensitive information. This repository should be named `conf` and be owned by the same user/organization that owns this `gitsync` repository.

The required structure for the `conf` repository is:

```
conf/
├── gitsync/
│   ├── atomgit.env
│   ├── github.env
│   └── ...           # and other .env files
└── ssh/
    ├── config        # SSH client configuration
    └── id_ed25519    # Private SSH key for Git access
```

-   **`gitsync/`**: This directory contains `.env` files, each defining specific environment variables. The `run.sh` script loads all `.env` files in this directory. Examples include:
    -   `atomgit.env`: Defines `ATOMGIT_TOKEN`.
    -   `github.env`: Defines `GITHUB_TOKEN`.
    -   `modelscope.env`: Defines `OPENAI_API_KEY`.
    -   `modelscopeModel.env`: Defines `OPENAI_BASE_URL` and `OPENAI_MODEL`.
    -   `tavily.env`: Defines `TAVILY_API_KEY`.
-   **`ssh/`**: This directory contains the SSH configuration.
    -   `id_ed25519`: The private SSH key for authenticating with Git providers. The workflow ensures it has the correct permissions (`600`).
    -   `config`: The SSH configuration file to specify which key to use for which host.

### GitHub Actions Workflow

The automation in this project is managed by two workflow files located in the `.github/workflows` directory.

-   **`gitsync.yml`**: This is the core workflow for synchronization.
    -   **Trigger**: Runs every 5 minutes on a schedule (`cron`) and can also be started manually (`workflow_dispatch`).
    -   **Process**: It checks out the project code and the private `conf` repository, sets up the Bun environment, installs dependencies, and runs the `./run.sh` script to trigger the synchronization.
    -   **Self-Update**: After the sync, it checks for any changes within the repository (like an updated `sync.yml`) and pushes them back to the `main` branch.

-   **`keep-alive.yml`**: This workflow ensures the repository remains active to prevent GitHub from disabling scheduled workflows on inactive repositories.
    -   **Trigger**: Runs once a month.
    -   **Process**: It updates a `.date` file with the current month, commits the change, and pushes it.

In addition to the workflow files, you need to configure the following:

-   **Secrets**: A Personal Access Token (PAT) with `repo` scope must be created and stored as a repository secret named `GH_PAT`. This token is used to check out the private `conf` repository.
-   **Source/Destination**: The source and destination for the sync are hardcoded in `main.js`. You may need to change the arguments in the `sync()` function call:
    ```javascript
    await sync(join(ROOT, "sync.yml"), ATOMGIT, "js0", GITHUB, "js0-site");
    ```

## Dependencies

-   [Bun](https://bun.sh/) as the JavaScript runtime.
-   [@3-/gitsync](https://www.npmjs.com/package/@3-/gitsync) as the core synchronization library.
